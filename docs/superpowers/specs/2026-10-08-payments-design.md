# Оплата тренировок и абонементы — дизайн

Дата: 2026-10-08

## Цель

Тренировки платные. Клуб ведёт в боте учёт: сколько стоит занятие, какие абонементы куплены и сколько в них осталось, кто что должен, кто доплатил за велодром. Деньги принимаются вне бота (перевод, наличные); бот фиксирует, кто и что оплатил. Интерфейс и модель допускают позже подключить онлайн-оплату как ещё один способ закрыть начисление.

## Решения (из обсуждения)

- Приём платежей в боте не делаем; оплату подтверждает админ.
- Списание по записи при закрытии тренировки; тренер может исправить посещение в течение 72 часов, дальше только админ.
- Абонемент действует на **набор серий** (утренняя и вечерняя серии разных тренеров могут входить в один абонемент). Срок: по умолчанию 1 календарный месяц, либо бессрочный.
- Разовая оплата и доплата (велодром) задаются на уровне типа тренировки с переопределением в серии.
- Доплата платится каждым участником отдельно и не покрывается абонементом. Тренер не платит; его долю делят ученики: `тариф × (n + 1) / n`, где n число участников.
- Запись «Пойду» всегда разрешена. Без абонемента возникает долг.
- Все денежные действия (цены, тарифы, выдача абонементов, отметки об оплате и возврате) только у админа. Тренер отмечает посещение; это не денежное действие.

## Область

**В рамках задачи:**
- Пакет `bot/billing` (модели, `BillingService`), миграция Alembic, регистрация в `bot/registry.py`.
- Начисления при закрытии тренировки, правка посещения, оплата, возвраты.
- Экраны ученика («💳 Оплата», `/payments`), админа («💰 Оплаты») и тренера («Посещение»).
- Перенос `InventoryOrder.price` и `paid_status` на начисления вида `inventory`.
- Строка об оплате в посте и в напоминании за 2 часа.
- Тесты, обновление `ARCHITECTURE.md` и дерева меню в `README.md`.

**Вне рамок:**
- Онлайн-оплата, чеки, налоги.
- Напоминания об истечении абонемента и о долгах.
- Продление просроченного абонемента и перенос остатка между абонементами.
- Автоматические денежные корректировки по уже оплаченной доплате (только уведомление админу).

## Модель данных

Суммы в копейках, время в UTC. Все модели импортируются в `bot/registry.py`.

- `PriceRule(kind PK, single_price, surcharge_per_person)`: цены по умолчанию для типа тренировки. `surcharge_per_person = NULL` значит доплаты нет.
- `TrainingSeries`: новые необязательные поля `single_price`, `surcharge_per_person`. Пусто значит брать из `PriceRule` по `kind`.
- `Training`: поля `single_price`, `surcharge_per_person` копируются при создании тренировки (разрешённые значения серии или типа). Правка цен не меняет созданные тренировки.
- `SubscriptionPlan(id, name, sessions, price, valid_days NULL = бессрочный, active)`; `valid_days` по умолчанию «1 календарный месяц» задаётся при выдаче (см. ниже).
- `SubscriptionPlanSeries(plan_id, series_id)`.
- `Subscription(id, user_id, plan_id, sessions_total, sessions_left, starts_at, expires_at NULL, price, paid_at NULL, issued_by, created_at)`.
- `SubscriptionSeries(subscription_id, series_id)`: набор серий, скопированный при выдаче. Правка тарифа выданные абонементы не меняет.
- `Charge(id, user_id, training_id, kind, amount, status, subscription_id NULL, paid_at, paid_by, refund_due, refunded_at, created_at)`.
  - `kind`: `session` / `surcharge` / `inventory`.
  - `status`: `pending` / `covered` / `paid` / `void`.
  - Уникальность `(training_id, user_id, kind)` для `session` и `surcharge`; для `inventory` ссылка на заказ.

Срок «1 календарный месяц» считается от даты выдачи в `club_timezone`: до той же даты следующего месяца (если такой даты нет, последний день месяца), конец дня, затем в UTC. Для остальных значений `valid_days` срок = `starts_at + valid_days`.

Долг ученика = сумма `Charge` в статусе `pending`. Остаток абонемента хранится в `Subscription.sessions_left`.

## Поведение

### Выбор абонемента

Подходит абонемент ученика, если: серия тренировки есть в `SubscriptionSeries`, `sessions_left > 0`, `expires_at` пуст или не раньше начала тренировки. Из подходящих берётся истекающий раньше, бессрочные последними. Просроченный абонемент просто не подходит; фоновой задачи нет. Остаток просроченного сгорает.

### Запись

«Пойду» не создаёт начислений и не списывает остаток; запись по-прежнему один SQL-оператор с проверкой лимита. Ученик видит подсказку «Будет списано с абонемента (осталось N)» или «К оплате: X ₽», а при наличии доплаты ориентир «доплата ≈ A–B ₽». Ориентир считается по текущему и максимальному числу участников.

### Закрытие тренировки

Для каждого участника в статусе «Пойду» (в одной транзакции на участника):

1. Подбирается абонемент и условным `UPDATE ... SET sessions_left = sessions_left - 1 WHERE id = ? AND sessions_left > 0` с проверкой rowcount. Успех создаёт `Charge(session, covered)`.
2. Иначе `Charge(session, pending)` на `Training.single_price`.
3. При `surcharge_per_person` создаётся `Charge(surcharge, pending)` на `тариф × (n + 1) / n`, округление вверх до копейки.
4. Участник получает сообщение о списании или сумме к оплате.

Обработчик идемпотентен (уникальность `Charge`). Отмена тренировки гасит pending-задачи и ничего не начисляет.

### Посещение

Когда тренировка закрыта, тренеру приходит личное сообщение с кнопкой «Проверить посещение». Экран перечисляет участников переключателями ✅/❌; «➕ Пришёл без записи» выбирает ученика через picker, добавляет запись и начисляет по правилам закрытия. Действия проходят через `bot/usecases.py`; сервис проверяет, что пользователь тренер тренировки или админ, и что с конца тренировки прошло не более 72 часов (админу окно не ограничено).

«Не пришёл» по состоянию начисления:

| Было | Станет |
|---|---|
| `covered` | `void`, `sessions_left + 1` (срок не продлевается) |
| `pending` | `void` |
| `paid` | `void`, `refund_due = true` (в списке админа «К возврату») |

Ученик получает уведомление. Доплата остальным пересчитывается: `pending` обновляется автоматически с уведомлением, по `paid` админу приходит уведомление с разницей, автоматически ничего не меняется.

### Оплата и возвраты (админ)

- «Оплачено» на начислении: `pending` → `paid` условным `UPDATE` с проверкой rowcount. То же для оплаты абонемента (`paid_at`).
- «Возвращено» на начислении с `refund_due`: ставит `refunded_at`.

### Экраны

- **Ученик:** «💳 Оплата» (`/payments`): абонементы с остатком и сроком, «К оплате», история.
- **Админ:** «💰 Оплаты»: должники (карточка ученика с кнопкой «Оплачено» на начисление и на все), выдача абонемента (ученик через picker, тариф, подтверждение, «Оплачено»), тарифы (создание, правка, отключение; набор серий переключателями), цены (по типу и переопределение в серии), «К возврату». Удаление тарифов и цен по образцу «Админов»: `❌ <имя>`, подтверждение, сервис проверяет и удаляет, список перерисовывается.
- **Тренер:** экран «Посещение».
- Строка об оплате в посте тренировки и в напоминании за 2 часа.

## Флаг фичи

Вся оплата, включая абонементы, — одна фича за флагом `BILLING_ENABLED` в настройках приложения (`Config`, переменная окружения). По умолчанию выключен; меняется только перезапуском бота.

- При `false` поведение бота прежнее: нет пунктов меню «💳 Оплата» и «💰 Оплаты», команды `/payments`, начислений, сообщения тренеру о посещении, строк об оплате в карточках, напоминаниях и при записи. Старые кнопки `pay:*`, `att:*`, `menu:pay` отвечают «Оплата отключена».
- Таблицы и миграция есть всегда.
- `bootstrap` при каждом старте записывает флаг в `settings["billing_enabled"]`; use case'ы, публикация и задачи читают его оттуда, Telegram-слой получает его при старте (workflow data) и подключает вместо роутеров оплаты заглушку. Сервисы `bot/billing` флага не знают.
- Начисления создаются только в момент закрытия тренировки, поэтому тренировки, закрытые при выключенной оплате, не начисляются и после включения.

## Архитектура

- Новый feature-пакет `bot/billing` (`models.py`, `service.py`); aiogram только в `bot/telegram/`.
- Фичи не импортируют сервисы друг друга; закрытие тренировки, правка посещения и оплата идут через `bot/usecases.py`.
- Права проверяются в `BillingService`, не берутся из callback-данных, FSM или picker.
- Обработчики в `bot/telegram/handlers/billing.py`: `take_form` до вызова сервиса, `restore_form` при `DomainError`, `safe_edit`, catch-all роутера `billing:`. Клавиатуры и callback-данные (`pay:*`, `att:*`) в `bot/telegram/menu.py`; новые пункты главного меню добавляются в `BOT_COMMANDS`.
- Конкурентность: списание только условным `UPDATE` + проверка rowcount (как §8 ARCHITECTURE.md).
- Логирование через `logging.getLogger(__name__)`.

## Тестирование (`tests/billing/`)

- Выбор абонемента: срок, остаток, несколько подходящих, бессрочный.
- Конкурентное списание: параллельные закрытия не уводят остаток ниже нуля.
- Идемпотентность закрытия тренировки.
- Расчёт доплаты и пересчёт при правке посещения.
- Возвраты по трём состояниям начисления; окно 72 часа; права тренера и админа.
- Копирование цен и набора серий (правка тарифа не меняет выданное).
- Чистые построители клавиатур без Telegram; фейки из `tests/fakes.py`.
