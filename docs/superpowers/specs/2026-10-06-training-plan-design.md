# План тренировки — дизайн

Дата: 2026-10-06

## Цель

Тренер или администратор может добавить к конкретной тренировке структурированный текстовый **план**
(например, «разминка 15′ / 4×8′ в зоне 4 / заминка»). План виден участникам сразу в посте тренировки,
отдельным блоком, независимо от поля `description` (оно остаётся как есть).

## Договорённости

- Формат плана — свободный текст (не файл и не ссылка).
- План виден в посте сразу, как только пост опубликован (за `publish_window_h`, по умолчанию 24 ч).
- План живёт **только на тренировке** (`Training`), в серии (`TrainingSeries`) поля нет.
- Добавлять и менять план могут только админ и тренер, который может управлять этой тренировкой
  (`ScheduleService.can_manage`). Обычный участник — отказ.
- Максимальная длина плана — **1500 символов** (`PLAN_MAX_LEN`): пост в Telegram ограничен 4096 символами,
  часть занимают карточка и описание.
- Вне цели: файлы/картинки, ссылки как отдельный тип, план в серии, шаблоны планов,
  «скопировать план из прошлой тренировки», отдельное уведомление участникам об изменении плана.

## Дизайн

### Модель данных

- `Training.plan: Mapped[str] = mapped_column(Text, default="")`; пустая строка — плана нет.
- Миграция Alembic (`alembic revision --autogenerate`): колонка с `server_default=""`, чтобы существующие
  строки получили пустой план.

### Сервис (`bot/schedule/service.py`)

- `TrainingEdit.plan: str | None = None`.
- `ScheduleService.update_training`: если `edit.plan is not None` — проверить
  `len(edit.plan) <= PLAN_MAX_LEN`, иначе `InvalidAction("План слишком длинный: N из 1500 символов")`;
  затем записать `training.plan = edit.plan`. Все проверки — до первой мутации. Права и состояние
  (`scheduled`, ещё не началась) проверяются уже существующим кодом.
- Константа `PLAN_MAX_LEN = 1500` живёт в `bot/schedule/service.py`; формы импортируют её оттуда.

### Перенос плана при правке серии

`update_series` пересоздаёт будущие тренировки: неопубликованные удаляются, опубликованные отменяются
(`series_edit`), а новые генерируются заново из шаблона. Чтобы правка серии не стирала работу тренера:

- Перед удалением/отменой собрать `{локальная дата: plan}` для будущих тренировок серии с непустым планом.
- После `_generate_for_series` записать сохранённый план в новую тренировку на ту же локальную дату
  (тот же способ сопоставления, что уже используется для `ReplacedTraining`).
- Если на дату новой тренировки нет (изменились дни недели), план теряется — это допустимо.
- Новые тренировки в этот момент ещё не опубликованы или публикуются сразу (`usecases.update_series`
  вызывает `publish`), поэтому план должен быть записан до коммита в `update_series`.

### Формы (`bot/schedule/forms.py`)

- `TRAINING_FIELD_PROMPTS["plan"] = "Введите план тренировки (или «-», чтобы убрать)"`.
- `apply_training_field("plan", text)` → `TrainingEdit(plan="" if text.strip() in _NO else text.strip())`.
  Валидация длины — в сервисе (единый источник правды); форма показывает его `DomainError` через
  существующий `restore_form`.

### Рендер (`bot/publishing/render.py`, `bot/publishing/service.py`)

- `CardData.plan: str`, заполняется из `training.plan` в `PublishService`.
- `render_card`: после описания, если `plan` непустой, добавляется пустая строка и блок
  `📋 План\n<текст>`. Блок выводится для любого статуса, в котором выводится описание.

### Telegram-интерфейс (`bot/telegram/handlers/trainer.py`)

- В карточке тренировки у тренера рядом с «✏️ Описание» появляется «📋 План»
  (`tr:edit:<tid>:plan`), по тому же механизму, что и остальные поля.
- Метка поля в `labels` — «План». Handler по-прежнему: `take_form` до вызова сервиса,
  `restore_form` при `DomainError`, экран правится через `safe_edit`; сохранение идёт через
  `usecases.update_training`, который вызывает `refresh_posts`.
- Нового роутера и нового FSM-состояния не нужно, если существующий поток `tr:edit:*` уже
  универсален по имени поля; иначе добавляется минимальная ветка для `plan` (уточняется при реализации).

### Ошибки

| Ситуация | Результат |
|---|---|
| План длиннее 1500 символов | `InvalidAction` с текущей и максимальной длиной; форма остаётся открытой |
| Нет прав на тренировку | `PermissionDenied` (как для остальных полей) |
| Тренировка отменена/прошла/началась | `InvalidAction("Тренировку уже нельзя изменить")` |
| «-» или пустой текст | План очищается |

### Тесты (TDD)

- `tests/schedule`: тренер правит план своей тренировки; админ — чужой; участник и тренер без прав
  получают отказ; «-» очищает; 1500 символов проходит, 1501 — `InvalidAction`; при `update_series`
  план переносится в замену (опубликованная и неопубликованная), а при смене дней недели не падает.
- `tests/publishing`: `render_card` показывает блок «📋 План» только при непустом плане и не меняет
  вывод без него.
- Usecase: после `usecases.update_training(plan=…)` пост в фейковом `Messenger` обновлён.
- Существующий тест конкурентной записи (`tests/participation`) не затрагивается.
